Scorer Training Log

End-to-end model: detection (staffer) + transcription (noter) in a single forward pass.

The scorer is a two-stage model trained jointly. The staffer half (ViT backbone + HierarchicalDecoder) predicts stave bounding boxes; a differentiable grid_sample crop bridge extracts per-stave image patches at those predicted coordinates; the noter half (encoder-decoder Transformer) transcribes each crop into a Kern token sequence. All weights are updated end-to-end through both losses. Dataset: PDMX subset with ≤2 staves/system (System2.csv). Validation runs multiple times per epoch; charts show the last checkpoint of each epoch.

Baseline standalone models: staffer stave-primary-grid-full (sys IoU 0.985, stave_err 0.41 px) and noter enhanced3 (99.58% token accuracy).

merge1 trains on PDMX (System2.csv); boulez & walton fine-tune on KernSheet (real scans). For the KernSheet runs the Val acc / Sys IoU / Stave err columns are on independent, unseeded validation splits and are not directly comparable run-to-run — the matched 300-page eval (identical pages for both models) is the honest comparator.

merge1

2026-06-02 · tag: train/merge1 · 8 epochs · initialized from stave-primary-grid-full + enhanced3

First end-to-end training run. Both halves are initialized from the best standalone checkpoints, then fine-tuned jointly. The staffer loss (L1 + GIoU + objectness) and noter loss (cross-entropy over token sequences) are summed and back-propagated in one pass through the differentiable crop bridge.

The training shows a characteristic early dip: at ep0 the model inherits strong standalone scores (sys IoU ~0.89 by end of epoch), but ep1–ep2 see a temporary regression as the model adapts to the joint gradient signal. Recovery is steady from ep3 onward, and by ep7 all metrics are still improving — the run is not fully converged.

boulez, walton & ravel — KernSheet fine-tune

2026-06-04 · tags train/boulez / train/walton / train/ravel · from stave-primary-grid-full-kernsheet + enhanced3-center+jitter-kernsheet · shared 5543 vocab

First end-to-end runs on KernSheet (real scanned piano scores), rebuilt fresh from the two KernSheet-fine-tuned standalone branches at the shared 5543 vocab — no checkpoint-growing needed. Three runs answer two questions — should the detector be frozen? and does longer joint training help?:

~ boulez (8 ep) — staffer unfreezes at step 500 (freeze_staffer_steps=500, the merge1 default), then trains jointly. The detector keeps receiving its full detection loss for 6 more epochs.
~ walton (8 ep) — staffer frozen for the whole run (--freeze-staffer-steps 3000 > 2000 total steps). The noter adapts to predicted crops; the detector never moves. The freeze ablation.
~ ravel (20 ep) — boulez recipe, longer (boulez was still improving at ep7). Converged ~ep14.

Barline-agreement rerank — scorer eval --rerank

The cross-staff barline-position agreement reranker (journal; scripts/scorer_system_agreement.py diagnostic) re-scores each system's beams to prefer the barline signature its staves agree on, falling back to argmax when none is shared. It is self-supervised — no oracle count — so it runs at inference for free. Evaluated on the same seeded 500 pages (eval debussy --size 500, default --seed 0, so every run draws identical pages) as a clean paired A/B at matched beam widths (--beam), so the rerank effect and the beam-width effect separate cleanly:

The rerank is a small, free, real win — +0.3 pp at beam 4, +0.4 pp at beam 8 — and the two levers are independent. The diagnostic ceiling was larger (exact joint-correct 17.9 % → 33.8 % on a stricter all-staves-agree metric), but on the softer matched-similarity eval the gain is modest because most systems already agree and the reranker only helps when a shared signature exists. It costs nothing at inference, so it stays on.

But that geometry gain does not carry into end-to-end transcription: on KernSheet — the whole point — mahler-augment is −0.3 pp (90.7 vs 91.0 rerank; 90.4 vs 90.6 off), inside the eval wobble, i.e. flat-to-slightly-worse. Detection geometry simply wasn't the real-scan bottleneck; transcription is, and the boxes were already good enough that tightening them buys nothing downstream. Meanwhile augment carries a PDMX cost: it concedes clean-PDMX base accuracy (staffer base 0.48 → 0.58 px) and the weaker objectness/count shows up as miscount 5 → 12 / 500 (7 missed PDMX staves vs 1). PDMX matched-stave similarity is up +0.6 pp, but that is only over staves it did find, so it doesn't offset the extra misses. Net: a real detector-level result with no end-to-end payoff and a small PDMX-counting tax — mahler stays as production. If augment is pursued again, the gap is in transcription, not detection, so the lever belongs on the noter path; and prob=0.5 on the staffer base was too strong for PDMX counting.

sibelius-detach — stop the joint-FT box-shrink (detach the crop bridge)

2026-06-26 · tag train/sibelius-detach · 20 ep · the sibelius recipe (sibelius-mixed staffer + noter, --kern-sheet … 0.67, --train-len 3500 -e 20) plus the new --detach-crop-box flag box-shrink fixed · zero transcription cost

A diagnostic (scripts/staffer_box_deltas.py --scorer) found that the joint fine-tune systematically shrinks the detector's stave boxes: on sibelius the top (system-0 RH) stave's height ran −14 px short on a ~37 px staff (~38%), the box pulling inward to its staff-line core, while the standalone staffer kept correct height. Cause is the same coupling the duration-head detach hit: the differentiable crop bridge backprops the transcription loss into the box coordinates, and crop()'s own context padding means a tighter box doesn't hurt transcription — so lambda_tr pulls the boxes in and lambda_det can't hold full height. A bridge-benefit A/B (scripts/bridge_benefit.py: trained scorer vs. a zero-shot merge of the same standalone branches) confirmed the shrink is transcription-neutral — the joint-FT win (KS 90.2 → 94.8%, +4.7 pp, and tighter counting) comes from the noter adapting to predicted crops, not box movement. So the fix cuts the gradient: --detach-crop-box (opt-in ScorerConfig.detach_crop_box) stop-gradients the box coords feeding crop() in ScorerModule._step, leaving detection geometry to the det loss alone.
