End-to-End Optical Music Recognition

Scan → layout detection → differentiable crop bridge → staff transcription → Kern tokens

This document describes the architecture that composes Staffer (hierarchical layout detector) and Noter (staff transcriber) into a single differentiable model. Each model keeps its own patch embedding and Transformer stack unchanged; they are joined only by a differentiable grid_sample crop bridge that samples each detected stave straight from the page image and feeds it to the noter. Because the crop is differentiable with respect to the predicted box position, the transcription loss flows back into the detector — the detector learns to place boxes that transcribe well, not merely boxes with high IoU. That gradient coupling is the entire payoff of "end-to-end," and it does not require sharing a low-level embedding.

Design choice — do not share the patch embedding (for now). An earlier draft fused both models onto one shared 4×4 patch embedding. We rejected it: the saving is ~4 K params and one cheap conv (negligible next to the ViT and the autoregressive decoder), while the cost is the most fragile weight transfer in the whole design — it discards the noter's pre-trained encoder and forces the staffer ViT to re-adapt to features from two stacked random convs. Sharing also creates the coarse-RoI-resolution problem it then elaborately solves. Keeping both models intact and bridging at full pixel resolution dissolves that problem and lets both checkpoints transfer cleanly. Sharing the low-level embedding is deferred to §8 — Deferred, to revisit only if profiling demands it.

1 — Staffer: Layout Detection (standalone)

Staffer takes a full grayscale page image, computes patch-level features with a ViT backbone, and decodes staves as the primary stream: each stave query is pinned to a frozen vertical anchor and predicts its (top, bottom); systems predict only (left, right) and their box is derived as the hull of the staves grouped under them (stave-primary-grid).

2 — Noter: Transcription (standalone)

Noter takes a cropped, height-normalised staff image (B, 1, 64, 768) and produces a sequence of Kern tokens. The patch size is (height=64, width=4) — the full staff height collapsed into one patch row of 192 columns. Each time step holds up to max_chords=8 chord slots, padded with SIL where unused.

3 — The Bridge: Differentiable Crop

Not RoIAlign. The obvious choice — torchvision.ops.roi_align — was verified empirically to not backprop to the box coordinates (boxes.grad is None); it only passes gradient to the input feature map. With roi_align the transcription loss would train the noter but never refine the detector, so there would be no end-to-end coupling at all. The bridge therefore uses affine_grid + grid_sample (a spatial-transformer crop), whose bilinear sampling is differentiable in the sampling grid — hence in the box position.

For each detected stave the bridge reconstructs the standalone noter's crop window, sampling directly from the raw page image at full resolution. Critically it is a 1:1 (un-stretched) window: a fixed input_shape-pixel (64×768) slice starting one stave-height above the stave top, left-aligned at the system's left edge, with the real stave width reported as source_widths so the right of the canvas is padded and masked (make_src_padding_mask) — exactly as the standalone noter does. This 1:1 geometry matters because the last system of a score usually ends mid-page; stretching it to fill 768px (a naïve output_size=(64,768) resample) would distort note spacing and corrupt timing. Because the window size is fixed and only its position tracks the box, the gradient flows to the stave top/bottom and system left (where to place the crop) — not to a spurious scale.

The noter branch is byte-for-byte the standalone model — same Conv2d(k=(64,4)) SourceEmbedding, same Encoder, same Decoder — so its checkpoint loads with no surgery. There is no coarse-feature problem and no height-merge conv to invent.

4 — Scorer (End-to-End Model)

The Scorer composes the two unmodified standalone models with the differentiable crop bridge between them. Staffer runs on the full page (its own Conv2d(k=16) PatchEmbedding → ViT → Decoder → Heads) and emits stave boxes. The bridge crops each predicted stave straight from the page image (a 1:1 grid_sample window → (64, 768)). Noter runs on those crops (its own SourceEmbedding → Encoder → Decoder → MLP) and emits Kern tokens.

Both checkpoints transfer wholesale — nothing discarded, nothing re-adapted — and the bridge adds zero parameters. Compute is the staffer ViT once over the page plus the noter once per detected stave (cheap for the ≤2-staff systems we start with): identical to running the two standalone models back-to-back, with one addition — the transcription loss now backpropagates through the grid_sample crop into the stave/system box position.

5 — Training Strategy

Three stages. Dashed borders indicate weights that may start frozen. Joint loss in Stage 3 = detection loss + transcription cross-entropy (optionally weighted).

Stage 1 — Staffer pre-training

Train full standalone Staffer (its own 16×16 PatchEmbed). No shared conv yet.

Result: sys IoU 0.971 · stave err ≈ 1.0 px (stave-primary-grid, D=128; full-size D=256 retrain for the merge)

Stage 2 — Noter pre-training

Train standalone noter on GT staff crops, with box-jitter augmentation (perturb the crop box by staffer's measured predicted-box error distribution) so it tolerates the detector's wobble at merge time. SourceEmbedding + Encoder will be discarded.

Result: 99.58% val token accuracy (enhanced3)

Stage 3 — End-to-end fine-tuning

Load both full checkpoints, insert the differentiable crop bridge, fine-tune jointly. No new conv layers.

Dashed = optionally frozen at start. The transcription gradient reaches the boxes through the bridge.

The total is just the sum of the two standalone models (staffer 13.5 M + noter 19.1 M) — the decoupled bridge adds no parameters. Keeping both patch embeddings costs ~2.5 M params over the shared-embedding draft, a deliberate trade for clean checkpoint transfer.

Training VRAM (B=16, Scorer fine-tuning, bf16-mixed): bf16 compute weights 65 MB + fp32 master weights 130 MB + AdamW fp32 m/v states 260 MB ≈ 455 MB; bf16 activations through staffer (2 580 patches, 4 layers) + noter (≤2 staves × 192 patches, 8 layers) ≈ 500–700 MB. There is no 41 280-position shared feature map to hold, so activation memory is lower than the shared-embedding draft. Estimated total ≈ 1.2–1.4 GB — fits very comfortably on RTX 4060/5060 Ti 16 GB.

6 — Design Rationale

This section traces the key decisions made in conversation that led to the architecture above.

Starting point: naïve RoIAlign from 16×16 backbone

The first Scorer proposal reused the Staffer's 16×16 patch ViT feature map (B, 256, 60, 43) as the RoIAlign source, with output_size=(4, 192).

Problem: a typical stave is only 2–4 feature rows tall at 16px/patch — very coarse for transcription, where vertical position encodes pitch.

Attempt: full 4×4 patch backbone

Moving to 4×4 patches on the full page gives 240×172 = 41 280 positions. Running a ViT on 41 280 tokens is quadratically expensive — roughly 256× more attention computation per layer than today's 2 580-token model ((41 280 / 2 580)² ≈ 256).

Rejected on compute grounds. But fine-grained shared features remained the right idea.

Clarification: noter patch size is (64, 4) not (64, 1)

During discussion a concern was raised about changing the noter's patch size from "(64, 1)" to "(4, 64)". A check of noter_model.py confirmed the actual values: patch_width=4, patch_height=64, giving Conv2d(k=(64,4)) and 192 patches per staff.

This matters because pitch is encoded vertically: the relative position of noteheads within the 64px staff height determines the note. Shortening the patch height would break this inductive bias and invalidate the pre-trained weights.

Considered: shared 4×4 embedding + branch convolutions

One Conv2d(1→256, k=4) on the page, then a k=4 downsample for staffer and an RoIAlign + Conv2d(k=(16,1)) height-merge for noter — both tuned so their effective receptive fields match the standalone patch sizes.

Rejected (deferred). The saving is ~4 K params and one conv pass — negligible. The costs are real: it discards the noter's pre-trained encoder (the decoder would cross-attend to features it never saw), and forces the staffer ViT to re-adapt from two stacked random convs instead of its trained k=16 embed. Receptive-field matching is necessary but not sufficient — it does not match the feature distribution the pre-trained stacks learned to read.

Decision: decouple with a differentiable bridge

The coarse-RoI problem (card 1) only exists because we insisted on a shared source. Crop from the raw page instead and it evaporates — the noter samples at full pixel resolution exactly as standalone.

And the actual prize — transcription gradients reaching the detector — comes from the crop being differentiable in the box position, not from sharing anything. So: keep both models intact, bridge them with a differentiable crop. Both checkpoints transfer wholesale; the pre-merge diagnostic already measured only ~0.86% degradation feeding predicted (vs GT) crops to the unchanged noter — we start from a near-working pipeline and merely add the gradient path.

Implementation caveat (verified): the crop must use affine_grid + grid_sample, not torchvision.ops.roi_align — the latter does not backprop to the box coordinates (boxes.grad is None), so it would carry no gradient to the detector at all.

The core invariant: the bridge reproduces the standalone noter's crop window exactly — a 1:1, left-aligned, right-masked 64 × 768 slice anchored at (top − h, left) — only differentiably. Neither model's architecture changes; Stage 1 and Stage 2 checkpoints transfer to Stage 3 with no surgery at all. The only thing the merge introduces is a gradient from the transcription loss into the box position.

7 — Implementation Guide

Everything needed to go from the two standalone checkpoints to a working Scorer model. No decisions are left open — only write code.

Non-destructive principle: the existing staffer and noter CLIs and models are unchanged. ScorerModel composes them by importing their sub-modules (e.g. StafferModel.backbone.blocks, NoterModel.target_embedder) — not by modifying those classes. Both standalone training pipelines continue to work exactly as before. Where helpful, expose a build_encoder() or similar factory on the existing model classes so ScorerModel can construct the right sub-graph without duplicating code.

7.4 Differentiable stave crop

Given Staffer outputs, build the (N_staves_total, 5) box tensor [batch_idx, left, top, right, bot] and crop directly from the page image with affine_grid + grid_sample. Not torchvision.ops.roi_align — verified to not backprop to the box coordinates, so it would carry no gradient to the detector. The window is a 1:1 (un-stretched) (64, 768)-pixel slice anchored at (top − h, left), left-aligned, with the real stave width as source_widths so the right is padded and masked — exactly the standalone noter crop. Only the window's position depends on the box, so the gradient reaches the stave top/bottom and system left (not a spurious scale). 

# Inputs (N = 16 sys queries, M = 16 stave queries; shown for one page):
#   image:           (1, H, W) = (1, 960, 688)  — the page fed to staffer
#   stave_tb:        (M, 2)  — [top, bottom] normalised [0,1]
#   sys_lr:          (N, 2)  — [left, right] normalised [0,1]
#   stave_logits:    (M,)    — stave objectness
#   boundary_logits: (M,)    — >0 ⇒ this stave starts a new system

H, W = 960, 688
OUT_H, OUT_W = 64, 768                     # noter input_shape

# Group active staves into systems, then inherit (left,right) from the owner.
# Active queries are non-contiguous, so the boundary cumsum runs over the
# active staves sorted top-to-bottom (identical to `staffer predict`).
active = (stave_logits > 0).nonzero(as_tuple=True)[0]
active = active[stave_tb[active, 0].argsort()]              # top-to-bottom
group  = (boundary_logits[active] > 0).long().cumsum(0) - 1 # → system id
lr     = sys_lr[group.clamp(0, N - 1)]                      # (n_active, 2)

# Raw stave box (pixels): (top,bottom) from the stave, (left,right) from its system.
top  = stave_tb[active, 0] * H;  bot = stave_tb[active, 1] * H
left = lr[:, 0] * W;             right = lr[:, 1] * W
h    = bot - top

# 1:1 window of (OUT_H, OUT_W) source px, anchored top-left at (top - h, left).
# Per-box affine theta in grid_sample's normalised [-1,1] coords (align_corners=False).
cy = (top - h) + OUT_H / 2                 # window centre (px)
cx = left + OUT_W / 2
theta = boxes.new_zeros((active.numel(), 2, 3))
theta[:, 0, 0] = OUT_W / W                 # 1:1 horizontal (no stretch)
theta[:, 0, 2] = cx / W * 2 - 1
theta[:, 1, 1] = OUT_H / H                 # 1:1 vertical
theta[:, 1, 2] = cy / H * 2 - 1
grid  = F.affine_grid(theta, [active.numel(), 1, OUT_H, OUT_W], align_corners=False)
src   = image.expand(active.numel(), -1, -1, -1)
crops = F.grid_sample(src, grid, align_corners=False, padding_mode="border")
crops = crops * renorm_scale + renorm_shift            # → noter normalisation space
widths = (right - left).clamp(1, OUT_W).long()         # real width → src padding mask

memory = noter.encode(crops, widths)       # noter SourceEmbedding + Encoder, unchanged
                                           # → (n_active, 192, 256)  ← noter memory

During training the active staves are routed by the frozen-anchor GT→query assignment and passed through the noter decoder; loss is masked to those staves. During inference, filter by stave_logits.sigmoid() > threshold before passing to the decoder. Exact for staves where 3·h ≥ 64px (the System2 norm); very short staves get page context instead of white vertical pad — a minor deviation to revisit if it bites.

7.5 Image dimensions

The Staffer resizes pages to (960, 688) px via StafferConfig.scale_to_patch(): max_height=1449 / divider=1.5 → 966 → round to 16 → 960; max_width=1024 / 1.5 → 682.7 → round to 16 → 688. The Scorer model must use the same size. Staffer's own Conv2d(k=16) embedding turns it into (60, 43) = 2 580 patches — identical to its standalone training — and the same (960, 688) page is the crop source for the bridge, so the box coordinates (normalised [0,1]) scale by exactly H, W.

7.6 Scorer dataset

ScorerDataset must provide per-sample:

  • image (1, 960, 688) — resized page, grayscale, float32
  • gt_sys_boxes (N, 4) — padded system boxes, ltrb normalised (same as StafferDataset)
  • gt_stave_boxes (M, 4) — padded stave boxes (M=16); ltrb, only top/bottom used in loss
  • gt_assign (M,) — stave→system index, -1 for padding (same as StafferDataset)
  • stave_tokens (M, T, max_chords) — token sequences per stave slot, PAD-filled for inactive slots

StafferDataset already provides the first four fields. NoterDataset provides staff crops + token sequences for a subset (≤2 staves). ScorerDataset should inherit or wrap StafferDataset and add token sequences by matching stave positions to the Kern token files from PDMX. Use only scores present in System2.csv initially (guarantees token coverage).

8 — Deferred: shared patch embedding

The §4 model deliberately does not share a low-level patch embedding between the two branches. That option — one Conv2d(1→256, k=4) feeding both, with per-branch convs restoring each model's patch granularity (detailed in §6) — is parked here as a future optimisation, to be revisited only if a concrete pressure justifies the integration risk.

Why deferred, not adopted: sharing saves ~4 K params and one cheap conv pass — irrelevant next to the ViT and the autoregressive decoder, and irrelevant to the phone-deployment target. It buys nothing measurable while imposing the most fragile weight transfer in the design (a discarded noter encoder, a re-adapted ViT). The decoupled bridge delivers the entire end-to-end payoff — joint gradients — with both checkpoints intact.

Conditions that would justify revisiting

  • Profiling shows the duplicated low-level conv is a real cost on the target device — e.g. inference latency on the phone is dominated by running both patch embeddings rather than by attention. (Unlikely: both embeddings are tiny.)
  • Evidence of low-level feature data-starvation — if the shared staff-line / notehead features would measurably improve generalisation when learned jointly rather than independently. No such evidence exists today; both models converge well on the ~500 K-page corpus.
  • A redesign already rewrites the low-level stack for another reason (e.g. a unified high-resolution backbone), making the shared embedding nearly free to adopt in passing.

If revisited, keep the noter encoder rather than discarding it (run it on the crops) — that removes the single largest risk the original shared-embedding draft carried.
