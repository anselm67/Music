End-to-End Optical Music Recognition

Scan → shared patch features → layout detection + staff transcription → Kern tokens

This document describes the architecture that merges Staffer (hierarchical layout detector) and Noter (staff transcriber) into a single differentiable model. Both branches share a low-level 4×4 patch embedding, then specialise through separate convolutions that restore each model's natural patch granularity before their respective Transformer heads.

1 — Staffer: Layout Detection (standalone)

Staffer takes a full grayscale page image, computes patch-level features with a ViT backbone, and decodes staves as the primary stream: each stave query is pinned to a frozen vertical anchor and predicts its (top, bottom); systems predict only (left, right) and their box is derived as the hull of the staves grouped under them (stave-primary-grid).

2 — Noter: Transcription (standalone)

Noter takes a cropped, height-normalised staff image (B, 1, 64, 768) and produces a sequence of Kern tokens. The patch size is (height=64, width=4) — the full staff height collapsed into one patch row of 192 columns. Each time step holds up to max_chords=8 chord slots, padded with SIL where unused.

3 — The Bridge: RoI Alignment

RoIAlign (Mask R-CNN, 2017) extracts a fixed-size feature crop from a 2D feature map for each detected region using bilinear interpolation — no coordinate rounding, hence "aligned".

In the E2E model, the shared 4×4 patch embedding produces a feature map at (240×172) spatial resolution (each position = 4×4 px of the input). A typical stave is 32–64 px tall = 8–16 feature rows — a significant improvement over the 2–4 rows that would result from a 16×16 backbone. RoIAlign samples output_size=(16, 192) per stave, then a height-merge conv collapses the 16 height bins into 1, restoring the noter's natural sequence shape.

Key insight: Conv2d with k=(16,1) applied to 4px features has a receptive field of 16×4 = 64px vertically and 1×4 = 4px horizontally — identical to the standalone noter's Conv2d(k=(64,4)) on raw pixels. Same inductive bias: each output position sees the full staff height (all 5 lines, for pitch) and a 4px-wide column (for timing).

4 — End-to-End Model

A single shared Conv2d(1→256, k=4, s=4) replaces both models' patch embeddings. The resulting (B, 256, 240, 172) feature map branches into two specialised convolutions: a 4×4 downsample for Staffer (restoring 16×16px patch semantics) and an RoIAlign + (16,1) height-merge for the noter (restoring 64×4px patch semantics). The ViT backbone runs only in the Staffer branch (2 580 patches, same cost as today).

Both branches' standalone weights transfer directly: Staffer checkpoint minus its PatchEmbedding; noter checkpoint minus its SourceEmbedding and Transformer Encoder.

5 — Training Strategy

Three stages. Dashed borders indicate weights that may start frozen. Joint loss in Stage 3 = detection loss + transcription cross-entropy (optionally weighted).

Stage 1 — Staffer pre-training

Train full standalone Staffer (its own 16×16 PatchEmbed). No shared conv yet.

Result: sys IoU 0.971 · stave err ≈ 1.0 px (stave-primary-grid, D=128; full-size D=256 retrain for the merge)

Stage 2 — Noter pre-training

Train standalone noter on GT staff crops, with box-jitter augmentation (perturb the crop box by staffer's measured predicted-box error distribution) so it tolerates the detector's wobble at merge time. SourceEmbedding + Encoder will be discarded.

Result: 99.58% val token accuracy (enhanced3)

Stage 3 — End-to-end fine-tuning

Insert shared conv + branch convs. Load checkpoints. Fine-tune jointly.

Dashed = optionally frozen at start

6 — Design Rationale

This section traces the key decisions made in conversation that led to the architecture above.

Starting point: naïve RoIAlign from 16×16 backbone

The first E2E proposal reused the Staffer's 16×16 patch ViT feature map (B, 256, 60, 43) as the RoIAlign source, with output_size=(4, 192).

Problem: a typical stave is only 2–4 feature rows tall at 16px/patch — very coarse for transcription, where vertical position encodes pitch.

Attempt: full 4×4 patch backbone

Moving to 4×4 patches on the full page gives 240×172 = 41 280 positions. Running a ViT on 41 280 tokens is quadratically expensive — roughly 256× more attention computation per layer than today's 2 580-token model ((41 280 / 2 580)² ≈ 256).

Rejected on compute grounds. But fine-grained shared features remained the right idea.

Clarification: noter patch size is (64, 4) not (64, 1)

During discussion a concern was raised about changing the noter's patch size from "(64, 1)" to "(4, 64)". A check of noter_model.py confirmed the actual values: patch_width=4, patch_height=64, giving Conv2d(k=(64,4)) and 192 patches per staff.

This matters because pitch is encoded vertically: the relative position of noteheads within the 64px staff height determines the note. Shortening the patch height would break this inductive bias and invalidate the pre-trained weights.

Solution: shared 4×4 embedding + branch convolutions

Run one cheap Conv2d(1→256, k=4, s=4) on the full page, then branch:

  • Staffer: Conv2d(k=4,s=4) on features = 16×16px effective patch → ViT unchanged
  • Noter: RoIAlign → Conv2d(k=(16,1)) = 16×4=64px tall, 1×4=4px wide

The height-merge conv's pixel-level receptive field is identical to the standalone noter's Conv2d(k=(64,4)). Same inductive bias, same 192 output positions, fully compatible with pre-trained weights.

The core invariant: both branch convolutions are designed so that their effective pixel-level receptive fields match the patch sizes of the standalone models exactly. Neither Staffer nor noter "sees" a different scale of information — only the source of the low-level features changes (shared vs. per-model). This means Stage 1 and Stage 2 checkpoint weights transfer to Stage 3 without any architectural surgery beyond replacing the patch embedding layers.

7 — Implementation Guide

Everything needed to go from the two standalone checkpoints to a working E2E model. No decisions are left open — only write code.

Non-destructive principle: the existing staffer and noter CLIs and models are unchanged. E2EModel composes them by importing their sub-modules (e.g. StafferModel.backbone.blocks, NoterModel.target_embedder) — not by modifying those classes. Both standalone training pipelines continue to work exactly as before. Where helpful, expose a build_encoder() or similar factory on the existing model classes so E2EModel can construct the right sub-graph without duplicating code.

7.4 Stave box construction for RoIAlign

Given Staffer outputs, construct the (N_staves_total, 5) box tensor for torchvision.ops.roi_align. All operations are differentiable. 

# Inputs (N = 16 sys queries, M = 16 stave queries; shown for one page):
#   stave_tb:        (M, 2)  — [top, bottom] normalised [0,1]
#   sys_lr:          (N, 2)  — [left, right] normalised [0,1]
#   stave_logits:    (M,)    — stave objectness
#   boundary_logits: (M,)    — >0 ⇒ this stave starts a new system

H_feat, W_feat = 240, 172          # shared feature map spatial size

# Group active staves into systems, then inherit (left,right) from the owner.
# Active queries are non-contiguous, so the boundary cumsum runs over the
# active staves sorted top-to-bottom (identical to `staffer predict`).
active = (stave_logits > 0).nonzero(as_tuple=True)[0]
active = active[stave_tb[active, 0].argsort()]              # top-to-bottom
group  = (boundary_logits[active] > 0).long().cumsum(0) - 1 # → system id
lr     = sys_lr[group.clamp(0, N - 1)]                      # (n_active, 2)

# Each stave box = (left,right) from its system + (top,bottom) from the stave.
# Convert to feature-map pixel coords (spatial_scale=1.0 in roi_align).
x1 = lr[:, 0] * W_feat;  x2 = lr[:, 1] * W_feat
y1 = stave_tb[active, 0] * H_feat;  y2 = stave_tb[active, 1] * H_feat

batch_idx = torch.zeros_like(x1)                           # page's index in B
boxes = torch.stack([batch_idx, x1, y1, x2, y2], dim=-1)   # (n_active, 5)

# features_2d: (B, 256, H_feat, W_feat)  ← shared embed output reshaped
crops = torchvision.ops.roi_align(
    features_2d, boxes.float(),
    output_size=(16, 192),
    spatial_scale=1.0,   # boxes already in feature-map coords
    aligned=True,
)  # → (n_active, 256, 16, 192)

# Collapse height dimension: Conv2d(256→256, k=(16,1), s=(16,1))
crops = height_merge(crops)        # (n_active, 256, 1, 192)
memory = crops.squeeze(2).permute(0, 2, 1)  # (n_active, 192, 256)  ← noter memory

During training the active staves are routed by the frozen-anchor GT→query assignment and passed through the noter decoder; loss is masked to those staves. During inference, filter by stave_logits.sigmoid() > threshold before passing to the decoder.

7.5 Image dimensions

The Staffer resizes pages to (960, 688) px via StafferConfig.scale_to_patch(): max_height=1449 / divider=1.5 → 966 → round to 16 → 960; max_width=1024 / 1.5 → 682.7 → round to 16 → 688. The E2E model must use the same size. With the shared 4×4 embed the feature map is (240, 172); after the DownConv k=4 the Staffer sees (60, 43) = 2 580 patches — identical to its standalone training.

7.6 E2E dataset

E2EDataset must provide per-sample:

  • image (1, 960, 688) — resized page, grayscale, float32
  • gt_sys_boxes (N, 4) — padded system boxes, ltrb normalised (same as StafferDataset)
  • gt_stave_boxes (M, 4) — padded stave boxes (M=16); ltrb, only top/bottom used in loss
  • gt_assign (M,) — stave→system index, -1 for padding (same as StafferDataset)
  • stave_tokens (M, T, max_chords) — token sequences per stave slot, PAD-filled for inactive slots

StafferDataset already provides the first four fields. NoterDataset provides staff crops + token sequences for a subset (≤2 staves). E2EDataset should inherit or wrap StafferDataset and add token sequences by matching stave positions to the Kern token files from PDMX. Use only scores present in System2.csv initially (guarantees token coverage).
