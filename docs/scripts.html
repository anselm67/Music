scorer_system_agreement.py diagnostic scorer kernsheet

Per-system cross-staff barline-agreement diagnostic on the end-to-end scorer (debussy) — the measurement behind a system-level reranker that would favour beam combinations whose staves agree on barline positions. Runs the real predicted-box pipeline (detect → crop → transcribe) and groups staves by the scorer's own owners (detection-derived, not a GT key). Within a system every spine shares the same record rows, so a barline falls on the same timestep index in each stave; the signature is the set of = positions (catches a shared count with a shifted bar). Per predicted multi-stave system it reports: argmax disagreement rate (what the rerank can act on), the consistency ceiling (a signature present in every stave's candidate set), and — on systems whose staves cleanly match GT staves by center-y (Hungarian, no miss/extra) — the correctness ceiling and the agreement↔correctness gap (is the logprob-best consistent combo actually GT, or do the staves agree on a shared error). Carries a beam_all that returns all candidates + slot-0 logprobs, since ScorerModule._beam_single keeps only the best (the reranker needs the full beam too).

Usage
uv run python scripts/scorer_system_agreement.py \
    --scorer debussy --kern-home /home/anselm/datasets/KernSheet \
    --pages 300 --beam 16 --device cuda
scorer_usable_ks_pages.py diagnostic scorer kernsheet

The real coverage ceiling for SCORER_FT_TRAIN. The scorer trains one page per sample, but ScorerDataset.__getitem__ silently skips any page that breaks its supervision contract, so the raw "validated pages" count badly overstates usable data — most of it is shared-PDF spillover (a per-work score spans the whole shared PDF, so every page belonging to a different work in that PDF is validated-but-empty; e.g. each WTC2 prelude carries ~132 empty pages, the full book's page count). This replicates the filter exactly (minus the image load): per validated KernSheet page it requires non-empty systems, every system 1–2 staves with bar numbers inside the query budget, and every stave's bar range to tokenize. Prints enrolled vs scorer-usable counts and a breakdown of why pages are dropped, so you can size the fine-tune train_len/valid_len to the usable corpus rather than over-cap into MixedSource recycling.

Usage
uv run python scripts/scorer_usable_ks_pages.py [KS_ROOT]

staff_height_probe.py diagnostic kernsheet

Quantifies the legacy thirds-split staff-height artifact (read-only). The legacy→native layout migration only had the grand-staff envelope (rh_top/lh_bot) and split it into exact thirds, so each staff box's inner (gap-facing) edge overshoots the real outermost staff line by ~(gap−staff_height)/3; the outer edge is the true envelope and is correct. For every staff box it re-measures the 5 staff lines from the cached page image (full-width dark-row peaks inside the box) and reports, per edge, how far the box sits outside the outermost measured line — median/p95/max and the count over 2px. Writes nothing; it exists to sanity-check the fixer before it mutates GT.

Usage
uv run python scripts/staff_height_probe.py --home ~/datasets/kern-sheet-edit [--prefix bach] [--verbose]
staff_height_fix.py data fix kernsheet

One-shot corpus fix for the thirds-split artifact measured by staff_height_probe.py. Re-measures the 5 staff lines inside each box and snaps only the inner edge in to the measured outermost line. Conservative by construction: the trusted outer edge is never touched, the inner edge only ever moves inward (the box only shrinks), an unmeasurable staff is left untouched, and a move beyond MAX_MOVE_PX (a likely mis-measure) is skipped. Dry-run by default; --write saves layout JSON in the given --home only (git there is the rollback). --worklist writes the changed score ids one-per-line for kernsheet edit --worklist <file> to review.

Usage
uv run python scripts/staff_height_fix.py --home ~/datasets/kern-sheet-edit \
    --write --worklist staff_height_fixed.txt
bridge_benefit.py diagnostic scorer

Does the scorer's joint fine-tune (the differentiable crop bridge) actually buy transcription accuracy over a plain two-stage staffer→crop→noter pipeline? Runs the identical end-to-end eval on the same seeded pages for two models: the trained scorer checkpoint vs. a zero-shot MERGE of the same run's standalone staffer + noter branches (ScorerModule.load_from_checkpoints, no joint training). At inference the bridge crops the same pixels a plain crop would, so the merge is the plain-crop baseline; the gap is the joint fine-tune's contribution. First run (sibelius, 500 KS pages): scorer 94.8% vs merge 90.2% = +4.7pp, and the merge over-segments (41 vs 7 miscount pages).

Usage
uv run python scripts/bridge_benefit.py \
    --scorer sibelius --staffer sibelius-mixed --noter sibelius-mixed \
    --kern-home /home/anselm/datasets/KernSheet --size 500
staffer_box_deltas.py diagnostic staffer

Per-dimension box delta diagnostic. For each matched stave pair (predicted vs. GT, Hungarian-matched), reports Δleft, Δright, Δtop, Δbottom (pred − GT, pixels) with signed mean (bias direction) and absolute statistics (error magnitude). Supports both PDMX and KernSheet sources.

system_edge_consistency.py diagnostic pdmx kernsheet

Tests the GT-structure assumption that, within a page, all systems share a left edge (except the first, which may be indented) and a right edge (except the last, which may end short). For each page with ≥3 systems it reports the per-page edge spread (max − min, px) with and without the boundary system, plus the first-system indent and last-system shortfall. Motivates a cross-system edge-consistency loss term. On PDMX the interior edges are pixel-exact; on KernSheet ~80–85% of pages hold within 5px (multi-section pages are the exceptions).

Usage
uv run python scripts/system_edge_consistency.py --kern-home /home/anselm/datasets/KernSheet
uv run python scripts/system_edge_consistency.py --home /home/anselm/datasets/PDMX --limit 3000
train_scorer_pipeline.sh orchestrator staffer noter scorer

Trains a full scorer from one base NAME: PDMX base + KernSheet fine-tune for both the staffer and the noter, then merges the two fine-tuned branches and fine-tunes the scorer on KernSheet (five runs total). A bash orchestrator (not a uv run python script): fail-fast, tags train/<name> per CLAUDE.md, and skips any stage whose checkpoint already exists so the long run is resumable. Best-run hyperparameters live in a config block at the top of the file. Run by the user from a main checkout; the user launches training, not Claude.

Usage
scripts/train_scorer_pipeline.sh <NAME> [SCORER_NAME]   # SCORER_NAME defaults to NAME
DRYRUN=1 scripts/train_scorer_pipeline.sh my-model     # print commands, run nothing
FORCE=1  scripts/train_scorer_pipeline.sh my-model     # retrain stages even if a checkpoint exists
Notes

Needs the shared KernSheet vocab (KernSheet/build/vocab.json); builds it via noter extend-vocab if missing. The noter PDMX base trains directly on that vocab (no grow-checkpoint). KernSheet fine-tune split sizes are pinned to the dataset (staffer/scorer 2321 pages, noter 26166 staff items).
