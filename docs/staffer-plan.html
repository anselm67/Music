Staffer: Chained System-Box Representation

Motivation

System boxes are currently predicted as independent (cx, cy, w, h) per query. Two problems:

  1. Asymmetry: both top and bottom derive from two predicted values (cy ± h/2). In practice the model learns cy more accurately than h, so bottom-edge quality is gated on h accuracy.
  2. No structural coupling: the model must independently discover that bottom[i] ≈ top[i+1]. Nothing enforces this.

Fix: keep tight system boxes (top = top of first stave, bottom = bottom of last stave) but replace independent (cx, cy, w, h) per system with a chained representation that explicitly predicts the inter-system gap. For N systems this requires 3N + 1 numbers instead of 4N, saving N−1 values. Every directly-predicted edge gets its own gradient signal.

The 7-number layout (N = 2 systems)

Solid borders = predicted.   Dashed lines = derived (not direct model outputs).   Orange brace = explicit gap prediction.

Key insight: system boxes are tight (top = top of first stave, bottom = bottom of last stave). The gap between systems is predicted explicitly (number ④ for system 0). The tight bottom b₀ is derived from the stave head; t₁ = b₀ + gap₀ follows from that. One number is saved per additional system vs. independent cxcywh boxes. For N systems: 3N + 1 numbers total.

Coordinate semantics

New per-system encoding, all values normalized to [0, 1]:

SystemPredicted numbersDerived
First (i = 0)left, right, top, gap_belowbottom from stave head
Middle (0 < i < N−1)left, right, gap_belowtop = bottom_{i-1} + gap_{i-1}, bottom from stave head
Last (i = N−1)left, right, bottomtop = bottom_{i-1} + gap_{i-1}

gap_below = distance (in normalized y) from the system's tight bottom to the next system's tight top. Stave positions come from the (cy, h) stave head predictions — unchanged.

Model changes

PredictionHeads (staffer_model.py)

sys_box_head output changes from 4 → 3 per query: predicts (left, right, bottom).
New sys_top_head = nn.Linear(D, 1) applied only to query 0: predicts top₀.
The forward pass reconstructs full (B, N, 4) boxes by chaining: 

top_0  = sys_top_head(sys_feats[:, 0:1, :]).sigmoid()   # (B, 1, 1)
lrb    = sys_box_head(sys_feats).sigmoid()               # (B, N, 3)
tops   = torch.cat([top_0, lrb[:, :-1, 2:3]], dim=1)   # (B, N, 1)
sys_boxes = torch.cat([lrb[:, :, :2], tops, lrb[:, :, 2:]], dim=-1)
# sys_boxes: (B, N, 4) = (left, right, top, bottom)

Output tensor shape (B, N, 4) is preserved — downstream code sees the same shape.

Dataset changes

StafferDataset (staffer_dataset.py)

sys_boxes tensor keeps shape (num_system_queries, 4), semantics change: 

systems = page.systems
W, H = page.image_width, page.image_height

for sys_idx, system in enumerate(systems):
    top    = system.box.top / H
    bottom = systems[sys_idx + 1].box.top / H if sys_idx < len(systems) - 1 else 1.0
    sys_boxes[sys_idx] = torch.tensor([
        system.box.left  / W,
        system.box.right / W,
        top,
        bottom,
    ])

Chaining holds exactly: top[i+1] = systems[i+1].box.top / H = bottom[i].

Loss changes

StafferLoss (staffer_loss.py)

  • Replace box_cxcywh_to_xyxy with box_lrtb_to_xyxy: reorder columns (l,r,t,b) → (l,t,r,b).
  • generalized_iou: call new conversion function.
  • _box_loss: L1 loss on (left, right, top, bottom) directly — formula unchanged.
def box_lrtb_to_xyxy(boxes: Tensor) -> Tensor:
    l, r, t, b = boxes.unbind(-1)
    return torch.stack([l, t, r, b], dim=-1)

CLI changes (cli/staffer.py)

  • show: unpack (left, right, top, bottom); construct Box directly from pixel coords.
  • predict: derive stave cx/w from (left + right) / 2 and right - left.
  • unbox helper: update for new 4-element semantics.

What does NOT change

  • Stave predictions: (cy, h) unchanged.
  • gt_stave_boxes, gt_assign, assignment loss — all unchanged.
  • Tensor shape (B, N, 4) for sys_boxes through the whole pipeline.
  • StafferConfig — no new fields.
