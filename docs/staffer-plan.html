Staffer: Direct LTRB System-Box Representation

Problem

System boxes are currently predicted as (cx, cy, w, h) per query. The top and bottom edges are both derived quantities: 

top    = cy − h/2
bottom = cy + h/2

If the model biases cy toward the top stave group (plausible — treble is visually dominant) and underestimates h, the errors partially cancel for top but compound for bottom. This matches what we observe: cy_err 0.9 px (top) vs 16 px (bottom). The bottom edge has no independent gradient path.

Fix

Predict system boxes as (left, top, right, bottom) — each edge directly, normalized to [0, 1]. No chaining, no derived values, no new heads. The model architecture is otherwise unchanged; only the interpretation of the 4-dimensional sys_box_head output changes.

Why not chaining? The previous plan tried to also save one predicted value per system pair by chaining top[i+1] = bottom[i]. For N=2 systems that saves 1 number out of 8 — not worth the added complexity or the error-propagation risk. The model can learn structural coupling from the data.

New coordinate semantics

All values normalized to [0, 1] by image width/height. Tensor shape (B, N, 4) is preserved — the indices just change meaning:

IndexOld (cxcywh)New (ltrb)
0cxleft
1cytop
2wright
3hbottom

Changes required

1. StafferDataset (staffer_dataset.py)

Replace to_cxcywh with direct tight-box coordinates:

- sys_boxes[sys_idx] = torch.tensor(
-     system.box.to_cxcywh(page.image_width, page.image_height)
- )
+ W, H = page.image_width, page.image_height
+ sys_boxes[sys_idx] = torch.tensor([
+     system.box.left   / W,
+     system.box.top    / H,
+     system.box.right  / W,
+     system.box.bottom / H,
+ ])

system.box is a tight bounding box (top of first stave, bottom of last stave). No chaining formula needed.

2. StafferLoss (staffer_loss.py)

Delete box_cxcywh_to_xyxy entirely. The new format is already xyxy, so generalized_iou can use the boxes directly: 

- def box_cxcywh_to_xyxy(boxes: Tensor) -> Tensor:
-     cx, cy, w, h = boxes.unbind(-1)
-     return torch.stack([cx - w / 2, cy - h / 2, cx + w / 2, cy + h / 2], dim=-1)

  def generalized_iou(pred: Tensor, target: Tensor) -> Tensor:
-     pred   = box_cxcywh_to_xyxy(pred)
-     target = box_cxcywh_to_xyxy(target)
      ...

The L1 loss in _box_loss operates element-wise — no change needed there.

3. PredictionHeads (staffer_model.py)

sys_box_head already outputs 4 values with sigmoid(). No structural change. Add a comment to make the new semantics clear: 

- sys_boxes = self.sys_box_head(sys_feats).sigmoid()  # (B, N, 4)
+ sys_boxes = self.sys_box_head(sys_feats).sigmoid()  # (B, N, 4) — (left, top, right, bottom)

4. CLI (cli/staffer.py)

Update unbox and all unpacking sites:

- def unbox(size: tuple[int, int], t: Tensor) -> Box:
-     cx, cy, w, h = value
-     return Box.from_cxcywh(size, cx, cy, w, h)
+ def unbox(size: tuple[int, int], t: Tensor) -> Box:
+     l, top, r, b = t.tolist()
+     W, H = size
+     return Box((l, top), (r, b)).scale(W, H)

In show, update the system-box unpack:

- cx, cy, w, h = tuple(map(lambda x: x.item(), sys[sys_index]))
- box = Box.from_cxcywh(width_height, cx, cy, w, h)
+ box = unbox(width_height, sys[sys_index])

In predict, the stave box needs cx and w from the parent system (inherited x-coords). Derive them from ltrb: 

- cx, _, w, _ = pred_sys_boxes[sys_idx]
- stave_box_4d = torch.stack([cx, cy, w, h])
+ l, _, r, _ = pred_sys_boxes[sys_idx]
+ cx = (l + r) / 2
+ w  = r - l
  stave_box_4d = torch.stack([cx, cy, w, h])   # stave still uses cxcywh internally

What does NOT change

  • Stave predictions: (cy, h) unchanged.
  • sys_box_head architecture: still 4-output MLP + sigmoid.
  • gt_stave_boxes, gt_assign, assignment loss — all unchanged.
  • Tensor shape (B, N, 4) for sys_boxes through the whole pipeline.
  • StafferConfig — no new fields.

Verification checklist

  1. uv run pytest tests/staffer/test_staffer_loss.py — update fixtures to ltrb; all loss tests pass.
  2. staffer check — forward pass produces correct shapes.
  3. staffer show — GT boxes render correctly on sample pages (tight around staves).
  4. uv run mypy src tests — no new type errors.
  5. Retrain required — existing cxcywh checkpoints are incompatible.

Expected outcome

With direct LTRB targets, the model gets an independent gradient signal for each of the four edges. The bottom edge is no longer gated on the accuracy of both cy and h. We expect the 16 px bottom drift to reduce significantly, converging closer to the 0.9 px top accuracy.
