KernSheet via a shared Source protocol & Scorer fine-tune

Goal

Use the much more real KernSheet dataset (published / scanned piano scores with manually reviewed layout) to fine-tune the scorer end-to-end model, alongside the synthetic PDMX it trains on today.

Bottom line (as built): KernSheet's legacy envelope layout was migrated once to native Score JSON at KernSheet/layout/<id>.json (non-destructive; .krn / .pdf untouched). A single Source protocol abstracts both PDMX and KernSheet behind the same four methods; datasets and models never see either dataset's on-disk layout directly. The OMR editor has been ported into src/kernsheet/ and writes native Score JSON. Phases 1–3 are complete; Phase 4 (fine-tune) is next.

KernSheet layout JSON schema (original — now migrated away)

pages:[ { page_number, image_width, image_height,
          staves:[ { rh_top, lh_bot } ],   # one entry per grand-staff SYSTEM (envelope only)
          bars:[x,…],                    # barline x-coords on the system (not per-staff)
          validated, image_rotation } ]
Key semantic of the old format: each “staff” entry was a grand-staff system storing only the outer envelope (rh_top, lh_bot), not the inner treble/bass split and not absolute bar numbers. The migration script resolved the treble/bass split (thirds rule) and assigned absolute first_bar / last_bar per system, producing native Score JSON. Note also: bars (barline x-positions) live on System, not on individual Staff objects — this is the final schema for both PDMX and KernSheet.

All three datasets touch the dataset through the same small surface; everything else (tensor building, box normalisation, crop, padding, SOS/EOS) is dataset-agnostic glue that already lives in the dataset classes.

Design — the Source protocol

All methods are keyed by id: str (the Score.id slug, globally unique per dataset). Datasets cache lightweight id lists and call source.score(id) per item rather than holding every parsed Score in memory. 

class Source(Protocol):
    def scores(self) -> Iterable[Score]: ...                              # enumeration (lazy)
    def score(self, id: str) -> Score: ...                                # reload one layout
    def image(self, id: str, page_number: int) -> Tensor: ...            # raw page px (CHW); dataset transforms
    def records(self, id: str, first_bar: int,
                last_bar: int) -> list[str] | None: ...                   # tab-joined kern lines
  • records() wraps KernReader.get_text. Returns tab-joined record lines; the dataset splits per spine (text.split("\t")[spine]). Returns None if unavailable.
  • Vocab is out of the protocol — there is exactly one vocab, shared by all sources. It is built once and passed to each dataset alongside the source; PDMX and KernSheet both point at the same vocab.json.

Package layout

  • src/sheetmusic/ — the shared domain layer: the Source protocol and the Score hierarchy (Score / Page / System / Staff / Box, lifted out of src/pdmx/layout.py). Name chosen to avoid the score/scorer collision.
  • src/pdmx/ — PDMX handling + PdmxSource, a thin adapter over the existing PDMX. Picks flat-vs-paged PNG by file existence probe.
  • src/kernsheet/ — KernSheet catalog manager, KernSheetSource (reads migrated layout/*.json + derived assets), and the ported cv2 HighGUI staff editor (editor.py, CLI kernsheet edit <id>). The heuristic OMR detector (projection/peak finding + deskew) was dropped; layouts are seeded from the trained Staffer model (stave-primary-grid-full) and corrected by hand.

Nothing depends on a concrete dataset except through Source; both adapters depend on sheetmusic.

KernSheetSource — what was done in Phase 3

All complexity is behind the protocol; models see none of it:

  • Migration (src/kernsheet/migrate.py, run once): legacy envelope JSON → native Score at KernSheet/layout/<id>.json. 581 scores migrated clean. Non-destructive: .krn / .pdf unchanged.
  • Stave split: piano grand staff always has RH treble + LH bass. With delta = (lh_bot − rh_top) // 3: RH staff [rh_top, rh_top+delta], LH staff [lh_bot−delta, lh_bot]; middle third is the inter-staff gap. Persisted at migration; refine line detection later. All systems are 2-staff (non-2-spine kern trips the count-match guard).
  • Bar alignment: first_bar / last_bar per system set by walking the kern’s =N sequence in reading order (OMR get_bar_offset logic), so records() returns the right measures. Count-match guard flags and excludes pickups / repeats / malformed scores — never silently misaligns.
  • Derived caching: PDF→PNG cached at KernSheet/build/png/<id>-<NNN>.png via pdf2image.convert_from_path (poppler); resized to image_width pixels wide then rotated by image_rotation (reproduces OMR apply_page_transforms in annotation space). Tokens at KernSheet/build/tokens/<key>.tokens via Music kern.tokenize (numbered =N barlines).
  • Blank-page guard: pages with zero systems are skipped by the staffer / scorer datasets at item-build (real scans have blank cover pages).
  • page_number is 1-based throughout (PDMX convention); the KernSheet on-disk layouts were bumped to 1-based in a one-time migration pass.
Alignment is tractable. KernReader (src/kern/kern_reader.py) indexes tokens by the absolute =N numbers written in the kern, and get_text(first, last) slices between those markers — so we align annotated systems to the kern’s own numbering rather than inventing numbers.

Main risk

Bar-number alignment is the chief correctness hazard: any system whose annotated measure count diverges from the kern’s =N sequence (pickups, repeats, second endings, multirests) will misalign tokens to crops. Mitigation is the count-match guard (already in the migration; ~31 scores excluded) plus the crop/token spot-check (done for bwv_856-0). Excluded scores are flagged per-id, not silently dropped.
