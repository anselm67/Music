Model size note. basic–enhanced2-vflip ran at D=256 · H=8 · mlp=1024. From enhanced2-sampler onward the StafferConfig default had silently shrunk to D=128 · H=4 · mlp=512 (the small-model config, never restored; train has no override flag) — so enhanced2-sampler, enhanced2-ltrb, enhanced2-ltrb-anchor, enhanced2-ltrb-anchor-iter, stave-primary and stave-primary-grid are all half-size. The D column above is corrected to reflect the saved hparams.yaml. Consequence: the sys-IoU gap of the ltrb line vs enhanced2 (0.914 vs 0.919) is largely capacity, not the ltrb formulation being "harder" — the like-for-like comparisons within the ltrb line (all D=128) remain valid. stave-primary-grid validated as the best architecture at this budget (sys IoU 0.971; bottom drift flattened to ~2.5 px); the full-size retrain stave-primary-grid-full (D=256/H=8/mlp=1024) has since landed as the new best — the gain compounds with capacity (sys IoU 0.985; bottom bins down to ~1 px).

enhanced2-ltrb

2026-05-29–30 · tag: train/enhanced2-ltrb · 7 epochs · D=128 H=4

Hypothesis: the cy drift is structural — in cxcywh, both edges share the same gradient through cy, so bias in one direction compounds into large bottom errors. Switching to direct ltrb (left, top, right, bottom) gives each edge its own independent gradient signal. A GIoU area clamping fix was also required: random sigmoid predictions at initialisation can produce invalid boxes (right < left), causing negative area and a pathological false minimum. Training had to be restarted after the first run diverged (sys_iou → −27, loss → −52) before the clamp was applied.

Changes from enhanced2

~ System box format: cxcywh → ltrb (direct edge prediction)
~ Stave head: (cy, h) → (top, bottom) direct edge coordinates
+ GIoU: .clamp(min=0) on width/height (fixes pathological loss with invalid ltrb boxes at init)
+ Bottom-of-page sampler bias (inherited from enhanced2-sampler; bottom_bias=3.0)
~ Epochs: 12 → 7 (350k train_len; matches enhanced2's ~150k step count)

enhanced2-ltrb-anchor

2026-05-30 · tag: train/enhanced2-ltrb-anchor · 7 epochs · D=128 H=4

Hypothesis: the residual top→bottom error growth in enhanced2-ltrb comes from under-trained high query slots. Matching is index-based top-to-bottom (slot i → i-th system/stave from the page top), so the high slots only ever see rare bottom-of-page content and learn their position poorly. Fix (DAB-DETR style): give each query a learnable logit-space anchor initialised evenly down the page at (i+0.5)/N; the box head predicts a residual added to the anchor before the sigmoid, so slot i starts near its vertical position instead of collapsing to 0.5. Only the vertical edges are anchored (system top/bottom, stave top/bottom); left/right stay unanchored. Change is internal to PredictionHeads — output semantics unchanged.

Changes from enhanced2-ltrb

+ Learnable vertical anchors on system (top, bottom) and stave (top, bottom) queries
+ Box heads predict logit-space residual: (delta + inverse_sigmoid(anchor)).sigmoid()
· All else identical to enhanced2-ltrb (350k data, max_sys_bottom sampler, 7 epochs)

This validates the marginal-anchor limitation: a single per-slot scalar can only encode the count-averaged position of slot i, but the i-th system's true vertical position depends on how many systems are on the page (slot 1 ranges ~0.06→0.50 depending on count). The image-conditioned head must still absorb that count-dependent variance, and does so least well for the rarely-active high slots. The genuine fix for the bottom is count-conditional anchoring (anchor at (i+0.5)/num_gt via a two-stage decoder) or a vertical containment loss — next experiments.

enhanced2-ltrb-anchor-iter

2026-05-30–31 · tag: train/enhanced2-ltrb-anchor-iter · 7 epochs · D=128 H=4 negative

Directly attacks the marginal-anchor limitation left open by enhanced2-ltrb-anchor: a single per-slot scalar can only encode the count-averaged vertical position of slot i, so the image-conditioned head must absorb all count-dependent variance and does so worst for the rarely-active high slots (the bottom-of-page ~12 px error). The fix turns the static anchor into a count-conditional one via iterative box refinement across the four decoder layers, supervised at every layer (deep supervision).

Each layer's box head predicts a logit-space residual Δ added to a running vertical reference; the output box is σ(Δ + ref). The detached, re-linearised output ref ← logit(box.detach()) becomes the next layer's reference. Because the reference is now derived from the previous layer's content-dependent box (not a frozen per-slot constant), it adapts to how many systems are actually on the page. Only the vertical edges (system top/bottom, stave top/bottom) are refined; left/right stay unanchored and are predicted per layer. The learnable even-spacing anchor from the parent model seeds the first layer's reference.

Changes from enhanced2-ltrb-anchor

+ Iterative refinement: every decoder layer predicts a residual Δ to the running reference; ref ← logit(σ(Δ+ref).detach()) feeds the next layer
+ Deep supervision: sys L1 + GIoU and stave L1 computed at all 4 layers (averaged); obj + assign stay on the final layer
~ Anchor role: static per-slot constant → seed for layer-0 reference (now count-conditional via refinement)
· All else identical (350k data, max_sys_bottom sampler, 7 epochs)

stave-primary

2026-05-31 · tag: train/stave-primary · 7 epochs · D=128 H=4 prev best

Inverts the hierarchy used through enhanced2-ltrb-anchor: instead of systems leading and staves conditioned on them via group attention, staves are the primary stream and systems are derived. Two reasons. (1) Staves march down the page at ~constant pitch, so stave i's top is near-linear in the slot index — a strong, low-variance prior the static anchor captures well; system tops are separated by a variable number of staves, so their slot→position map is high-variance (which is why per-slot anchoring helped systems only weakly). (2) The GT system box is exactly the hull of its staves (System.box = Box(staves[0].top_left, staves[-1].bot_right)), so predicting it through a separate head was redundant and let the two disagree.

Mechanics: 16 stave queries — independent of systems (no group attention) — predict (top, bottom) + objectness as a residual to static learnable per-slot anchors (no iterative refinement; see enhanced2-ltrb-anchor-iter's negative result). A per-stave boundary flag (“starts a new system”) replaces the assignment head — cumsum recovers the contiguous grouping. A thin system stream predicts (left, right) + objectness only. The system box is derived as (sys.left, min stave tops, sys.right, max stave bottoms); a GIoU loss on this derived box routes gradient into the extreme staves. The dependency is strictly one-directional — image → stave y → grouping → system x — so a noisy system estimate can no longer leak into the staves.

~ System head predicts (left, right) only; vertical extent derived as the stave hull
~ Derived-system GIoU loss — gradient flows to the extreme staves of each system
− Iterative refinement + deep supervision dropped (iter was negative); static anchors kept
+ Hard containment by construction (subsumes the planned containment-loss experiment)

stave-primary-grid

2026-05-31 · tag: train/stave-primary-grid · 7 epochs · D=128 H=4 prev best

Same architecture as stave-primary, changing only how stave queries are matched to ground truth. In stave-primary the matching is positional — GT stave i (top-to-bottom) is always served by query i, and the per-slot anchor is learnable. That makes query i's target high-variance: "the i-th stave from the top" sits at a very different y depending on how many staves are on the page, and the high-index queries only fire on dense pages, so they train rarely and learn their band poorly — the residual bottom-of-page error every prior run shows.

grid freezes the anchors to a uniform grid at (i+0.5)/M and routes each GT stave to the query whose frozen anchor sits nearest it (1-D optimal assignment via scipy.linear_sum_assignment on |anchor_center − gt_center|). The slot→stave map is now free / non-contiguous — GT stave 4 may be served by query 6 — so each query's anchor becomes a true, count-independent spatial prior and every query trains at ~uniform frequency. 1-D matchings never cross, so the top-to-bottom order (and the boundary-flag cumsum grouping) stays valid. At inference there is no routing: the active queries (objectness > 0) are the staves.

~ Assignment threaded through all 4 loss terms + 2 metrics; objectness target scattered at matched query indices (not [:num_gt])
· Everything else identical to stave-primary (systems still positional/contiguous; 7 epochs, D=128, sampler)

berlioz / berlioz-kernsheet — the letterbox experiment

2026-06-06 · tags train/berlioz / train/berlioz-kernsheet · D=256 H=8 · full scorer pipeline rebuild negative (staffer)

The motivation was geometric fidelity. Every dataset resized each page to a fixed shape with v2.Resize, which scales x and y independently — so a page that isn't full height (a short end-of-piece system) was stretched vertically. berlioz replaces that with a shared LetterboxResize (resize by a single aspect-preserving factor, then white-pad the bottom/right), and scales the GT boxes by the same factor. A full from-scratch lineage was retrained under it: PDMX base (berlioz) → KernSheet fine-tune (berlioz-kernsheet) → scorer (scorer/berlioz).

PDMX base — effectively unchanged

PDMX pages are uniformly 2970×2100, whose aspect ≈ the 960×688 canvas, so the letterbox is height-bound and lands at the exact same vertical scale as the old stretch (0.3232); only the horizontal differs (a 9 px white strip vs a 1.4% squeeze). Since the staffer detects stave y-coordinates, the targets are vertically identical. The apparent val/stave_err_px gap (0.52 vs stave-primary-grid-full 0.41) is a measurement artifact: the random_split seed changed between the runs, so they validate on different (heavy-tailed) PDMX pages. Treat the base as a tie.
