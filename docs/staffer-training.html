staffyh

2026-05-21 · 12 epochs · D=256 H=8

Key architectural simplification: staves no longer predict a full box. Instead they predict only (cy, h), inheriting (cx, w) from the assigned parent system. Containment and alignment loss terms are removed. Loss drops dramatically — the model no longer has to solve box localisation for two separate outputs.

Changes from noeps

~ Stave head: full (cx cy w h) → (cy, h) only
− Containment loss term
− Alignment loss term
− Stave GIoU loss term

enhanced3

2026-05-23 · tag: train/enhanced3 · 12 epochs · D=256 H=8

Hypothesis: predicting stave cy relative to the parent system's cy (cy_delta) should reduce the top→bottom drift, as residuals are smaller and more uniform. Stave cy output becomes a delta; full cy is reconstructed as sys_cy + stave_cy_delta at inference. This was later reverted — the relative prediction did not hold up under eval.

Changes from enhanced2

~ Stave cy: absolute → relative to parent system cy (delta)

flat

2026-05-28–29 · tag: train/flat · 12 epochs · D=128 H=4

New architecture: stave queries become a flat global pool of 16 that attend directly to image memory, rather than being conditioned on system queries via group attention. Each stave self-assigns to a system through the assign head alone. System query count reduced from 16 to 10 (covers 99.1% of pages; max 15 staves/page in Staff16 dataset). Also runs at D=128 (same size as enhanced2-staffer-small), so architectural and capacity effects can be partially separated.

Changes from enhanced2

− stave_group_attn (MultiheadAttention) removed from each DecoderLayer
− stave_group_norm (LayerNorm) removed from each DecoderLayer
~ num_system_queries: 16 → 10
~ embed_dim: 256 → 128, num_heads: 8 → 4

enhanced2-sampler

2026-05-29 · tag: train/enhanced2-sampler · 8 epochs (6+2 resumed) · D=256 H=8

Hypothesis: the 16 px bottom-of-page cy drift is caused by underrepresentation of bottom systems in training data. Two changes: (1) replace the is_last_page sampler heuristic with a continuous max_sys_bottom weight (sqrt_inv[part_count] × (1 + 3.0 × max_sys_bottom)), and (2) expand training data from 200k to 350k samples (all available Staff16 pages), training for 8 epochs total (6 initial, +2 resumed with a cosine LR stretch).

Changes from enhanced2

~ Sampler: is_last_page → max_sys_bottom continuous bias (bottom_bias=3.0)
~ Dataset: 200k → 350k training samples (full Staff16 subset)
~ Epochs: 4 → 8 (6 epochs standard, +2 resumed)
+ bottom_bias added to StafferConfig

enhanced2-ltrb

2026-05-29–30 · tag: train/enhanced2-ltrb · 7 epochs · D=256 H=8

Hypothesis: the cy drift is structural — in cxcywh, both edges share the same gradient through cy, so bias in one direction compounds into large bottom errors. Switching to direct ltrb (left, top, right, bottom) gives each edge its own independent gradient signal. A GIoU area clamping fix was also required: random sigmoid predictions at initialisation can produce invalid boxes (right < left), causing negative area and a pathological false minimum. Training had to be restarted after the first run diverged (sys_iou → −27, loss → −52) before the clamp was applied.

Changes from enhanced2

~ System box format: cxcywh → ltrb (direct edge prediction)
~ Stave head: (cy, h) → (top, bottom) direct edge coordinates
+ GIoU: .clamp(min=0) on width/height (fixes pathological loss with invalid ltrb boxes at init)
+ Bottom-of-page sampler bias (inherited from enhanced2-sampler; bottom_bias=3.0)
~ Epochs: 12 → 7 (350k train_len; matches enhanced2's ~150k step count)
