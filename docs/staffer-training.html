enhanced2-ltrb

2026-05-29–30 · tag: train/enhanced2-ltrb · 7 epochs · D=256 H=8

Hypothesis: the cy drift is structural — in cxcywh, both edges share the same gradient through cy, so bias in one direction compounds into large bottom errors. Switching to direct ltrb (left, top, right, bottom) gives each edge its own independent gradient signal. A GIoU area clamping fix was also required: random sigmoid predictions at initialisation can produce invalid boxes (right < left), causing negative area and a pathological false minimum. Training had to be restarted after the first run diverged (sys_iou → −27, loss → −52) before the clamp was applied.

Changes from enhanced2

~ System box format: cxcywh → ltrb (direct edge prediction)
~ Stave head: (cy, h) → (top, bottom) direct edge coordinates
+ GIoU: .clamp(min=0) on width/height (fixes pathological loss with invalid ltrb boxes at init)
+ Bottom-of-page sampler bias (inherited from enhanced2-sampler; bottom_bias=3.0)
~ Epochs: 12 → 7 (350k train_len; matches enhanced2's ~150k step count)

enhanced2-ltrb-anchor

2026-05-30 · tag: train/enhanced2-ltrb-anchor · 7 epochs · D=256 H=8

Hypothesis: the residual top→bottom error growth in enhanced2-ltrb comes from under-trained high query slots. Matching is index-based top-to-bottom (slot i → i-th system/stave from the page top), so the high slots only ever see rare bottom-of-page content and learn their position poorly. Fix (DAB-DETR style): give each query a learnable logit-space anchor initialised evenly down the page at (i+0.5)/N; the box head predicts a residual added to the anchor before the sigmoid, so slot i starts near its vertical position instead of collapsing to 0.5. Only the vertical edges are anchored (system top/bottom, stave top/bottom); left/right stay unanchored. Change is internal to PredictionHeads — output semantics unchanged.

Changes from enhanced2-ltrb

+ Learnable vertical anchors on system (top, bottom) and stave (top, bottom) queries
+ Box heads predict logit-space residual: (delta + inverse_sigmoid(anchor)).sigmoid()
· All else identical to enhanced2-ltrb (350k data, max_sys_bottom sampler, 7 epochs)

But the bottom-of-page error growth is not solved: bins 12–14 still sit at ~12–13 px, comparable to enhanced2-ltrb and enhanced2. The n-weighted mean error (bins 0–13) is essentially tied with plain ltrb (4.4 px). This validates the marginal-anchor limitation: a single per-slot scalar can only encode the count-averaged position of slot i, but the i-th system's true vertical position depends on how many systems are on the page (slot 1 ranges ~0.06→0.50 depending on count). The image-conditioned head must still absorb that count-dependent variance, and does so least well for the rarely-active high slots. The genuine fix for the bottom is count-conditional anchoring (anchor at (i+0.5)/num_gt via a two-stage decoder) or a vertical containment loss — next experiments.

enhanced2-ltrb-anchor-iter

2026-05-30–31 · tag: train/enhanced2-ltrb-anchor-iter · 7 epochs · D=256 H=8 negative

Directly attacks the marginal-anchor limitation left open by enhanced2-ltrb-anchor: a single per-slot scalar can only encode the count-averaged vertical position of slot i, so the image-conditioned head must absorb all count-dependent variance and does so worst for the rarely-active high slots (the bottom-of-page ~12 px error). The fix turns the static anchor into a count-conditional one via iterative box refinement across the four decoder layers, supervised at every layer (deep supervision).

Each layer's box head predicts a logit-space residual Δ added to a running vertical reference; the output box is σ(Δ + ref). The detached, re-linearised output ref ← logit(box.detach()) becomes the next layer's reference. Because the reference is now derived from the previous layer's content-dependent box (not a frozen per-slot constant), it adapts to how many systems are actually on the page. Only the vertical edges (system top/bottom, stave top/bottom) are refined; left/right stay unanchored and are predicted per layer. The learnable even-spacing anchor from the parent model seeds the first layer's reference.

Changes from enhanced2-ltrb-anchor

+ Iterative refinement: every decoder layer predicts a residual Δ to the running reference; ref ← logit(σ(Δ+ref).detach()) feeds the next layer
+ Deep supervision: sys L1 + GIoU and stave L1 computed at all 4 layers (averaged); obj + assign stay on the final layer
~ Anchor role: static per-slot constant → seed for layer-0 reference (now count-conditional via refinement)
· All else identical (350k data, max_sys_bottom sampler, 7 epochs)

Negative result. Iterative refinement underperformed the static-anchor parent on every axis: sys IoU 0.894 vs 0.914, stave L1 0.00657 vs 0.00490, val loss 0.272 vs 0.219. Decisively, it did not fix the bottom-of-page error it targeted — bin 13 rose to 17.6 px (vs 12.9 px for the static anchor) — and top-of-page precision also degraded (bin 0: 1.5 px vs 0.9 px). The per-layer detached-reference threading appears to destabilise rather than help; the count-conditional anchoring hypothesis does not hold here.
Consequences: (1) enhanced2-ltrb-anchor remains the best ltrb model; (2) iterative refinement is dropped from the stave-primary successor, which keeps the static anchors only; (3) since count-conditional anchoring failed to bend the bottom down, the index-based matching scheme itself is implicated — reverting to Hungarian matching stays a live option.
