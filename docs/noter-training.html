Noter Training Log

Architecture diagrams, training curves, and results for the staff-image → token transcription model.

The noter model is an encoder-decoder Transformer. The encoder reads a cropped staff image (64×768 px, grayscale) and produces patch embeddings; the decoder autoregressively generates a sequence of Kern tokens, each with up to 8 simultaneous chord notes. Dataset: PDMX subset with ≤2 staves/system (System2.csv). Metric: per-token accuracy (ignoring PAD).

Dataset

All noter runs use System2.csv — PDMX scores where the first system of the first page has ≤2 staves, filtered to valid assets and entries where kern and SVG bar numbers agree on every system (--bar-match, required for token-to-image alignment).

pdmx query -o System2.csv 'index==index' --score 'pages.0.systems.0.staff_count <= 2' --valid --bar-match

enhanced3-kernsheet

2026-06-03 · fine-tune · 12 epochs · D=256

First fine-tune on KernSheet — real published/scanned piano scores with manually-reviewed layout — starting from the enhanced3 PDMX checkpoint. Every previous run trained on synthetic Verovio-rendered PDMX; this is the first time the model sees real engraving. Train and validation are both drawn from KernSheet (a random 90/10 split); no PDMX is mixed in for now. Because the domain is harder, the honest reference point is the grown checkpoint's cold-start on KernSheet (~92% val token accuracy before any fine-tuning), not the 99.58% PDMX number.

How the KernSheet dataset is built

KernSheet lives at ~/datasets/KernSheet (a git repo of nested composer/work/… scores indexed by catalog.json; each score ships a .pdf and a Humdrum .krn). It is exposed to the model through the same Source protocol PDMX uses, so the dataset/datamodule code is dataset-agnostic. The pipeline (all already run; design history in docs/journal.html):

StageWhat it does
Layout migration The legacy envelope layout (one rh_top/lh_bot per grand-staff system) was migrated once into native Score JSON at KernSheet/layout/<id>.json — non-destructive (.krn/.pdf untouched). 581 scores migrated clean.
Stave split (thirds) A piano grand staff is always RH treble + LH bass: with delta = (lh_bot − rh_top) // 3, RH = [rh_top, rh_top+delta], LH = [lh_bot−delta, lh_bot], middle third is the inter-staff gap.
Bar alignment Per-system first_bar/last_bar are set by walking the kern's =N sequence in reading order; a count-match guard excludes pickups / repeats / malformed scores rather than silently misaligning tokens to crops.
Derived assets PDF→PNG cached under build/png/ (rendered into annotation space: resized to image_width, then rotated); tokens via Music's kern.tokenize under build/tokens/ (numbered =N barlines).
Unmigrated-score guard KernSheetSource.scores() filters on layout_path.is_file() (not .exists()): the 31 unmigrated entries have an empty json_path whose path resolves to the layout/ directory, which exists — the old guard yielded them and then crashed reading a directory. Only surfaced once we iterated most of the dataset.

Each sample is one cropped staff image paired with the Kern token sequence for its bar range (spine order [1, 0] for treble/bass). The full dataset is 26,166 staff-items across 582 scores; this run uses 26,000 of them (--train-len 23400 + --valid-len 2600, ~99%).

Shared vocabulary (4,784 → 5,543)

Fine-tuning reuses enhanced3's embedding/output rows, so the vocab must preserve every PDMX token id and only append new KernSheet tokens at the tail (a from-scratch rebuild would reorder ids and invalidate the checkpoint). The noter extend-vocab command loads the frozen PDMX vocab and appends KernSheet tokens seen ≥ 2×:

noter extend-vocab /home/anselm/datasets/KernSheet

KernSheet's out-of-vocabulary rate against the PDMX vocab is only 0.26 % occurrence-weighted, but spread over a long tail of 1,415 distinct tokens (extreme registers like eeee#/64, rich tuplets /24 /72 /96, grace notes /q). Keeping the 759 that appear ≥ 2× (656 singletons fall to UNK) grows the vocab to 5,543.

Checkpoint surgery (grow to the new vocab)

Two tensors depend on vocab size and must be resized while keeping every learned row in place: the token embedding (V, D) (a plain row append) and the output head mlp.weight (max_chords·V, D) / mlp.bias. The head is slot-major / vocab-minor (the forward does view(B, T, max_chords, −1)), so old rows are spliced per chord slot via view(8, V′, ·)[:, :V], not copied as a flat prefix. New rows start from a fresh initialisation.

noter grow-checkpoint \
    checkpoints/noter/enhanced3/last.ckpt \
    checkpoints/noter/enhanced3-kernsheet-init.ckpt \
    /home/anselm/datasets/KernSheet/build/vocab.json

Verified: the grown checkpoint loads strict=True into a fresh 5,543-vocab module and produces bit-identical logits on the original 4,784 tokens — so old-token behaviour is exactly preserved and only the 759 new rows are unlearned.

enhanced3-center+jitter

2026-06-04 · PDMX base · 12 epochs · D=256

A from-scratch PDMX base retrain (not a fine-tune) carrying two changes into the base model: a corrected staff-centered crop and a train-only box-jitter augmentation. It is also born directly at the 5,543 KernSheet vocab so the KernSheet fine-tune (enhanced3-center+jitter-kernsheet) can --init-from it with no checkpoint surgery. Architecturally identical to enhanced3 (D=256, same optimiser/schedule); the deltas are the crop, the jitter, and the vocab.

Why retrain the base (not just fine-tune)

The centering fix changes the actual input the model sees. Noter's patch embedding uses full-height 64×4 columns, so moving the staff from the lower half of the crop to the centre changes the content of every patch. enhanced3 learned the old, lower-half placement; a thin fine-tune would only re-adapt those weights. Retraining the base lets it learn centred crops from scratch — the base is also where the bulk of learning happens (150k steps on 200k PDMX samples vs the fine-tune's ~17k steps on 23k).

Centered staff crop

The crop targets a fixed 64×768 window. The old code cropped from box.top − box.height with height min(64, 3·box.height), intending a 3×-staff-height window with the staff centred in the middle third. But a real staff is ~24–32 px, so 3·h ≈ 75–96 px always exceeded 64: the cap fired on every staff, the window started a full staff-height above the staff top, and the staff got shoved into the lower half — with the tallest staves clipped at the bottom edge (visible as a treble sliver atop a bass crop). The fix centres the staff midline in the 64 px window (crop_top = box.top + box.height//2 − 32), clamps to the page, and pads white (image_pad_value) at the edges; the crop width is likewise clamped so a jittered right edge past the page pads white, not black.

Box jitter (train-only)

Per-edge independent clipped-Gaussian perturbation of the box before cropping, modelling the staffer detector's box error measured on KernSheet (scripts/eval_predicted_boxes.py): horizontal ≫ vertical, right edge worst.

Edgeσ (px)clip (px)
top / bottom3±15
left5±26
right8±50

Applied to a fraction --jitter 0.5 of train samples only; the validation split stays on clean centred crops (the datamodule jitters a shallow-copied train view, so val accuracy stays comparable to a no-jitter run). Jitter is added here, on PDMX, because PDMX boxes come from precise Verovio SVG extraction — so the jitter is the only, controlled source of box error. It is deliberately not added to the KernSheet fine-tune (see that card).

Direct KernSheet vocab (no checkpoint surgery)

The KernSheet vocab (5,543) is a verified id-preserving superset of the PDMX vocab (4,784 — 0 ids differ, 759 appended). Training the base directly on it (via the new --vocab flag) is identical in outcome to training on 4,784 then growing: the 759 KernSheet-only rows never appear in PDMX data, so they stay at init — exactly what grow-checkpoint produced — but without the surgery or its risk. The fine-tune then --init-froms the base directly.

enhanced3-center+jitter-kernsheet

2026-06-04 · KernSheet fine-tune · 12 epochs · D=256 · KernSheet best

KernSheet fine-tune of the enhanced3-center+jitter base — the centered+jitter analogue of enhanced3-kernsheet. Same recipe as that earlier fine-tune (--lr 1e-4, --warmup-steps 200, 12 epochs, KernSheet 90/10 split) with two differences: it inits from the centered base (so no grow-checkpoint step), and it adds no box jitter.

Why no jitter on the fine-tune

KernSheet's per-staff boxes are not tight ground truth — they are a thirds approximation of the grand-staff envelope (migrate.py: treble = [rh_top, rh_top + (lh_bot−rh_top)//3], bass = [lh_bot − delta, lh_bot]). Only the outer edges (rh_top, lh_bot) are human-annotated; the inner edges carry ~15–25 px of systematic slop, comparable to the jitter clip itself. So the KernSheet data already trains box-imprecision tolerance — adding synthetic jitter on top would compound an already-loose box and risk pushing the staff toward the window edge. The base's jitter robustness carries through; the fine-tune just adapts the real-engraving domain.

The GT→predicted drop, though, barely moved (5.85 % → 5.65 %): it is dominated by detection misses (154 staves, identical since the staffer is unchanged) — each a full base→0 collapse, ≈ 72 % of the drop — which box jitter structurally cannot fix. berlioz / berlioz-kernsheet — the letterbox experiment

2026-06-06 · tags train/berlioz / train/berlioz-kernsheet · the noter side of the full scorer letterbox rebuild letterbox expt

The scorer pipeline was rebuilt from scratch under a letterbox page transform (aspect-preserving resize + white pad, replacing the old independent-x/y stretch — see the staffer card for the full story). The hypothesis was that un-stretching helps transcription: a stretched staff distorts note spacing, which a sequence model should care about. The noter is the half where that could pay off — and it's the one bright spot of the experiment, though a faint one.

Val numbers are each run's own teacher-forced validation (PDMX nearly identical under letterbox vs stretch, so the base tie is expected). Free-running = noter --kern-home … eval berlioz-kernsheet --size 500 (greedy edit-distance similarity). *The reference free-running figure is loose — it comes from the predicted-box diagnostic on GT crops, a slightly different tool, so read the two as tied rather than a clean −0.4%. As with all KernSheet rows these are unseeded splits and the old model can't be re-eval'd under the current letterbox code without being out-of-distribution.

The noter is marginally better on val, tied on free-running — a faint positive, not a clear win. Teacher-forced val edges the stretch baseline (KernSheet 97.55% vs 97.41%, lower loss; PDMX a tie), but the honest free-running number lands on top of it (89.4% vs ≈ 89.8%). So un-stretching helps transcription at most slightly. It is not enough to carry the experiment: the staffer got measurably worse under letterbox and the scorer nets to a wash (90.8% vs ravel 90.7%). The lineage is being reverted, so enhanced3-center+jitter-kernsheet remains the production noter (it pairs with the stretch staffer); berlioz-kernsheet only works with the letterbox pipeline. If letterbox is ever revisited, the right scope is noter crops only, stretch for the staffer.
